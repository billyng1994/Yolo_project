# Design

Add one standard-library-only module, `safety_yolo/setup.py`, beside existing guarded CLIs. Derive the checkout root and exact project requirements from `pyproject.toml`, validate the running interpreter belongs to root `.venv`, locate uv with `shutil.which`, and construct an argument list invoking `uv pip install --python <current interpreter> --torch-backend <auto or override>` with both pinned requirements and targeted reinstall flags. No shell, tool bootstrapping, or imported torch during replacement. Bound read-only probes and verification subprocess; let package downloads complete normally with visible progress.

After a successful actual install, run the target interpreter in a fresh subprocess with an embedded diagnostic program. Import torch/torchvision there only, verify exact public versions/backend alignment, execute tiny tensor and native torchvision operations, and report supported runtime device availability. NVIDIA and ROCm use torch's CUDA-facing API; MPS is separate; otherwise CPU. An installed CUDA backend that cannot initialize a visible GPU must be reported honestly rather than called a successful GPU repair. Unsupported XPU is actionable, not silently called supported.

uv owns backend compatibility and package resolution. `uv.lock` remains the reproducible baseline, while setup overlays only the matched torch pair for the local backend. README documents this distinction and supplies install, dry-run, CPU override and training examples. Tests mock process/tool boundaries but execute real stdlib help and verification subprocess contracts. Real local installation plus GPU ops and existing offline/smoke tests provide runtime evidence where available.

## Security considerations

Only explicit setup changes dependencies. Refuse non-project interpreters, never use `--system`, never elevate, never install drivers, never invoke shell strings, and never trust dataset text as instructions. Keep HTTPS certificate checks enabled and use uv/PyTorch official backend selection. Do not dump unrelated environment variables or signed export URLs. The installer does not read or modify images, cache, labels, or run outputs. Failed replacement is not transactional; report environment state and a recovery command without automatic fallback that masks failure. Hardware visibility and driver presence affect runtime separately from wheel installation.
